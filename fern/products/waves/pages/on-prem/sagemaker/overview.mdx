Smallest AI ships model containers to the [AWS Marketplace](https://aws.amazon.com/marketplace/pp/prodview-tf5i65efzgtco) so you can deploy them as **SageMaker Real-time inference endpoints** inside your own VPC. Requests never leave your AWS account, and AWS bills you directly for both the software and the underlying compute.

## When SageMaker is the right fit

- **Regulated workloads.** Endpoints run inside your VPC and inherit your existing AWS compliance posture (HIPAA-eligible, SOC, ISO, PCI, FedRAMP where the AWS region supports it).
- **You already run on AWS.** Native integration with CloudWatch, IAM, VPC endpoints, PrivateLink, KMS, CloudTrail, and Application Auto Scaling.
- **Consolidated billing.** Software charges land on your AWS Marketplace bill; no separate Smallest AI invoice.
- **Minimal operational overhead.** AWS owns the container runtime, autoscaling, patching, and health checks. You own the endpoint config.

## When Docker or Kubernetes is a better fit

- **Non-AWS deployments.** Bare-metal, on-prem, or another cloud → see the [Docker](/models/self-host/docker-setup/stt-deployment/quick-start) or [Kubernetes](/models/self-host/kubernetes-setup/quick-start) guides.
- **Streaming with long-lived connections.** SageMaker Real-time Inference caps a single invocation at **60 seconds** of processing time and a **25 MB** request payload. If you need multi-minute WebSocket streams (long-form transcription, long-running voice-agent sessions), Docker or Kubernetes is the fit.
- **Custom container internals.** SageMaker locks you to the container image published to Marketplace. If you want to swap tokenizers, patch models, or add custom middleware inside the runtime, self-host with Docker.

## Supported endpoint types

| Endpoint type | Supported | Notes |
|---|---|---|
| **Real-time inference** | Yes | Primary path. Sub-second latency; per-request billing. |
| **Serverless inference** | No | Cold-start latency incompatible with real-time speech. |
| **Batch transform** | Yes | For bulk STT transcription. See the [batch transcription cookbook](/models/self-host/amazon-sagemaker/cookbooks/batch-transcription). |
| **Asynchronous inference** | Roadmap | Not exposed in the initial listing. |

## Supported instance types

Instance sizing depends on which model family the endpoint hosts. Start with the smaller instance and step up if `ModelLatency` in CloudWatch drifts past your SLO.

| Model | Recommended | Minimum | Notes |
|---|---|---|---|
| Lightning v3.1 (TTS) | `ml.g5.xlarge` | `ml.g5.xlarge` | 1× A10G, 24 GB. |
| Pulse (STT) | `ml.g5.2xlarge` | `ml.g5.xlarge` | Scales with concurrent streams. |

<Warning>
CPU-only instances are not supported. Both model families require an NVIDIA GPU on the endpoint.
</Warning>

## Feature parity with the cloud API

| Feature | Cloud API | SageMaker | Notes |
|---|---|---|---|
| Real-time TTS synthesis | Yes | Yes | Same voice catalog. |
| Streaming TTS (WebSocket) | Yes | Partial | Chunked HTTP streaming works; SageMaker does not expose WebSocket. |
| Pre-recorded STT (up to 25 MB) | Yes | Yes | 25 MB is the SageMaker Real-time payload cap. |
| Pre-recorded STT (> 25 MB) | Yes | Use Batch Transform | Split files into 25 MB chunks or use the batch cookbook. |
| Streaming STT (WebSocket) | Yes | No | SageMaker Real-time is request/response only. Use Docker or Kubernetes. |
| Voice cloning | Yes | Roadmap | Not exposed in the initial listing. |
| Webhooks / async callbacks | Yes | No | Handle callbacks in your own application layer. |
| Voice agents (STT + LLM + TTS orchestration) | Yes | No | Compose the individual models yourself. |

## Regions

The listing is available in every AWS region that supports the `ml.g5.*` instance family. Confirm availability on the [SageMaker instance-type pricing page](https://aws.amazon.com/sagemaker/pricing/) before you subscribe.
