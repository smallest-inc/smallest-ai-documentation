## The model change in one paragraph

Previously, one attachment did two jobs: a number attached to an agent decided both *who answers it* and *what the agent dials from*. These are now separate. **Who answers a number is durable configuration** — attach a number or inbound trunk to the agent that answers it. **What a call dials from is a property of the call** — the request, campaign, or transfer names its caller ID at call time. There is no outbound number configuration on the agent.

## The new surface

| Task | Endpoint |
|---|---|
| Bring your own trunk (receive) | `POST /sip-trunk/inbound` |
| Bring your own trunk (dial out) | `POST /sip-trunk/outbound` |
| Make an agent answer a number or trunk | `POST /agent/{agentId}/answers` |
| Stop it answering | `DELETE /agent/{agentId}/answers/{sourceId}` |
| Pick a call's caller ID | `fromNumber` on `POST /conversation/outbound` |
| Pick a campaign's caller IDs | `fromNumbers` on `POST /campaign` |
| Set the number transfers dial from | `PUT /agent/{agentId}/transfer-source` |

Splitting the trunk into two resources is also what enables direct SIP-to-SIP: an inbound trunk with `allowedAddresses` and no phone numbers answers any extension from those peers — impossible with the old single import, which required a phone number.

## What still works during the migration window

The old API keeps working, translated to the new model underneath. Responses on deprecated paths carry a `Deprecation: true` header. **A removal date has not been announced yet**; it will be published on this page and in the changelog with notice.

| You are still doing this | Status |
|---|---|
| `POST /product/import-phone-number` | Works — creates an inbound and an outbound trunk, returns the same product id shape |
| `telephonyProductId` on agent create/update | Works — applied as the agent's answer sources (replace semantics; ids you do not own are refused) |
| `allowInboundCall: false` on an agent | Works — honoured as a kill switch at call routing |
| `allowInboundCall: true` | No effect (as before) |
| `fromProductId` on `POST /conversation/outbound` | Works — legacy alias, resolved to its number |
| Omitting the from-number on an outbound call | Works when the agent answers on exactly one number; otherwise `400` listing your options |
| `phoneNumberIds` on `POST /campaign` | Works — resolved to numbers at creation (numbers are no longer reassigned between agents) |
| Reading `agentId` on a number | Works — now means only "the agent that answers this number" |
| Reading `customProducts` on `GET /product/all-numbers` | Works — derived live from your trunks |

## What to change in your integration

1. **Creating trunks**: replace one `import-phone-number` call with the two `sip-trunk` calls (one per direction, and skip the direction you do not need).
2. **Attaching to an agent**: replace `telephonyProductId` with `POST /agent/{agentId}/answers` (`{ "sourceKind": "phoneNumber" | "sipTrunk", "sourceId": "..." }`). A source is answered by exactly one agent; attaching a taken one returns `409` naming the current agent.
3. **Outbound calls**: send `fromNumber` (E.164, exact match against numbers you own — no normalization is applied). Calls without it only succeed when the agent answers on exactly one number. There is no fallback to a platform number.
4. **Campaigns**: send `fromNumbers`. Several numbers rotate; retries reuse the number the recipient already saw; the list freezes at creation. Effectively required already: a campaign that resolves to zero numbers is refused.
5. **Transfers**: if an agent transfers calls, set its transfer caller ID once via `PUT /agent/{agentId}/transfer-source`. Migrated setups get this backfilled automatically. When unset, transfers on outbound calls use the call's own line; transfers on inbound calls are refused.

## Behavior changes worth knowing

- Inbound phone numbers are unique across the platform; outbound caller IDs are unique within your organization, and one outbound trunk exists per carrier address.
- An outbound trunk's `address` and `transport` are immutable — changing carriers means delete and recreate.
- `cpsLimit` (1-50, default 1) paces outbound calls per carrier address, shared by every trunk on that address.
- Deleting or releasing telephony resources is guarded: you get a `409` naming the agent, campaign, or transfer configuration still using them, instead of a silent breakage.
- `GET /agent/{agentId}` keeps `phoneNumber` as `string[]`, now meaning *what the agent answers on*. An agent answering on an extension-only trunk returns `[]` and is still reachable.

## Dashboard equivalents

SIP trunks moved from the Add Number dialog's "Import SIP" tab to a dedicated **SIP Trunks** page (sidebar, under Phone Numbers). An agent's answering sources and transfer number live on the agent's **Telephony** tab. Campaign creation has a **Call from** selector. Test calls have a **Call from** picker with a shared platform test number as the labelled default.
