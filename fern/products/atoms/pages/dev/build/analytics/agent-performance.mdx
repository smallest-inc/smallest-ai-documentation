Track how fast your agents respond and identify performance bottlenecks.

## Latency Metrics

Each call includes `turn_latency_metrics` — how long the agent takes to respond after the user stops speaking, measured per turn:

| Metric | Description |
|--------|-------------|
| `avg_latency` | Average response latency across all turns (ms) |
| `median_latency` | Median response latency (ms) |
| `min_latency` / `max_latency` | Fastest and slowest turns (ms) |
| `turns` | Number of turns measured |
| `latencies` | Per-turn latency values (ms) |

## Getting Latency Data

```python
from smallestai import SmallestAI

client = SmallestAI()  # reads SMALLEST_API_KEY from the environment

call = client.atoms.calls.get("CALL-1768842587790-69eb58")
metrics = call.data.turn_latency_metrics

print(f"Average latency: {metrics.avg_latency}ms")
print(f"Median latency: {metrics.median_latency}ms")
print(f"Slowest turn: {metrics.max_latency}ms")
print(f"Turns measured: {metrics.turns}")
```

## Performance Benchmarks

| Metric | Good | Acceptable | Needs Work |
|--------|------|------------|------------|
| Average turn latency | < 900ms | 900-2000ms | > 2000ms |
| Slowest turn | < 2000ms | 2000-4000ms | > 4000ms |

## Analyzing Performance

```python
def check_performance(call_id):
    call = client.atoms.calls.get(call_id)
    metrics = call.data.turn_latency_metrics
    
    issues = []
    
    if metrics and metrics.avg_latency and metrics.avg_latency > 2000:
        issues.append("High average latency - consider shorter prompts")
    
    if metrics and metrics.max_latency and metrics.max_latency > 4000:
        issues.append("Slow outlier turns - check tool execution time")
    
    if issues:
        print(f"Performance issues: {', '.join(issues)}")
    else:
        print("Performance is good!")
    
    return issues
```

## Improving Performance

<AccordionGroup>
  <Accordion title="Reduce LLM latency">
    The LLM is usually the slowest component. To speed it up, keep system prompts concise, use streaming responses (enabled by default), and consider a faster model.
  </Accordion>
  
  <Accordion title="Optimize tools">
    Tool execution adds latency. Make API calls fast, cache where possible, and use parallel execution with `parallel=True`.
  </Accordion>
  
  <Accordion title="Monitor trends">
    Track latency over time. Sudden increases may indicate API issues or prompt bloat.
  </Accordion>
</AccordionGroup>

## Quality Metrics

Combine latency with call outcomes:

```python
def quality_report(call_ids):
    fast_and_completed = 0
    slow_calls = 0
    
    for call_id in call_ids:
        call = client.atoms.calls.get(call_id)
        data = call.data
        
        metrics = data.turn_latency_metrics
        avg_latency = (metrics.avg_latency if metrics else 0) or 0
        
        if data.status == "completed" and avg_latency < 1000:
            fast_and_completed += 1
        elif avg_latency >= 1000:
            slow_calls += 1
    
    print(f"Quality calls: {fast_and_completed}/{len(call_ids)}")
    print(f"Slow calls: {slow_calls}/{len(call_ids)}")
```
